Foundations

Chapter 2 — Preliminaries

Let me start with the scientific foundations that underpin the rest of the thesis.

Discriminative vs. Generative

Discriminative

Model \(P(y|x)\) directly

  • Lower asymptotic error
  • Needs more labeled data
  • Logistic Regression, SVM, BERT

Generative

Model \(P(x,y) = P(x|y)P(y)\)

  • Faster convergence
  • Works with fewer examples
  • Naive Bayes, HMMs, GPT

The "two regimes" (Ng & Jordan, 2002)

The classical distinction between discriminative and generative models is central to this thesis. Ng and Jordan showed two regimes: generative models converge faster with limited data, but discriminative models eventually achieve lower error. [>>>] This observation motivates the "modern recipe" we use throughout: pre-train generatively, then fine-tune discriminatively. Let me explain what that looks like in practice.

The Modern Recipe

Generative Pre-training → Discriminative Fine-tuning

Phase 1: Pre-train

Generative objective on massive unlabeled data

MLM, next-token prediction, de-rendering

→ Learns robust representations

⟹

Phase 2: Fine-tune

Discriminative objective on labeled data

Classification, QA, fact verification

→ Lower asymptotic error

Best of both worlds: generative phase provides the "prior," discriminative phase optimizes the decision boundary

This is the recipe we follow in every chapter. Phase 1 uses a generative objective — masked language modeling, next-token prediction, or chart de-rendering — on large unlabeled corpora. Phase 2 fine-tunes on the target task with a discriminative head. The key insight: the generative phase learns general representations that transfer; the discriminative phase refines them for the specific task. [>>>] We show this works for tables, charts, and even temporal knowledge. With this recipe in mind, let me briefly review the architectures we build on.

Architectures at a Glance

Encoder-Only

BERT

Bidirectional attention → understanding

Decoder-Only

GPT

Causal attention → generation

Encoder-Decoder

T5

Both → sequence-to-sequence

Vision Transformer

ViT

Image patches as tokens → unified architecture

If text = tokens and images = patch-tokens, a single Transformer can process both

Our work spans all three text architectures. TAPAS and MATE use BERT (encoder-only), TabT5 uses T5 (encoder-decoder), and the charts work builds on Pix2Struct and PaLI (encoder-decoder with vision). [>>>] The key insight from Vision Transformers is that images can be represented as sequences of patches, enabling a unified architecture. This is foundational for our charts chapter, where we process chart images directly. Now, let's look at where existing models fall short.

Incorporating Tables
into Models

Chapter 3

EMNLP 2020 · EMNLP 2021 · EMNLP 2022 · ACL 2024

Let's start with Chapter 3 on tables — this is where the thesis began. The question is simple: how do we make a language model understand tabular data? Four papers spanning from 2020 to 2024, covering understanding, efficiency, and generation.

The Challenge

Language models are pre-trained on flat text, but tables have 2D structure

TAPAS: Adding row, column, and rank embeddings to BERT for table understanding

The core challenge: BERT sees a flat sequence of tokens, but tables have rows, columns, and hierarchical headers. TAPAS addresses this by adding specialized positional embeddings — row ID, column ID, and rank within each column. These structural signals let the model distinguish between cells in different positions without changing the underlying architecture. Importantly, TAPAS is initialized from a standard BERT checkpoint, adding only the new embedding layers.

Intermediate Pre-training

Teaching models to reason about tables before fine-tuning

Counterfactual Statements

Corrupt real sentences about Wikipedia tables by swapping entities with plausible alternatives

"Australia won 5 medals" → "Canada won 5 medals"

Synthetic Statements

Generate sentences from logical expressions that filter, combine, and compare table data

argmax, sum, count, compare → natural language

Our key contribution is intermediate pre-training: an extra stage between general pre-training and task fine-tuning. We create two types of synthetic training data from Wikipedia tables. Counterfactual statements take real sentences and corrupt them — swapping an entity to make the statement false. This teaches the model to verify facts against tables. Synthetic statements programmatically generate true/false assertions using SQL-like operations, teaching numerical and logical reasoning. This synthetic data costs nothing to generate and provides massive improvements.

TabFact Results

Table Fact Verification

+6 pts (BERT-base) · +9 pts (BERT-large) over previous SOTA

On TabFact — the main table fact verification benchmark — our intermediate pre-training with counterfactual and synthetic data gives dramatic improvements. [>>>] Plus 6 points with BERT-base and plus 9 with BERT-large over the previous state of the art. These are substantial gains for what is essentially a data augmentation strategy with zero additional annotation cost.

Data Efficiency

Pre-training with counterfactual + synthetic data matches Table-BERT using only 10% of the fine-tuning data

This plot shows perhaps the most important finding. With our intermediate pre-training, the model reaches Table-BERT's full-data accuracy using only 10 percent of the fine-tuning data. This is the Ng and Jordan insight in action: the generative-style synthetic pre-training provides a strong prior, so less labeled data is needed downstream. This has real practical implications — you don't always have large labeled datasets for every table task.

MATE: Efficient Attention for Tables

Multi-view Attention for Table Transformer Efficiency

Restrict attention to row/column views

  • Sparse attention → linear cost in sequence length
  • Drop-in replacement for BERT attention
  • Provably universal approximation
  • 2× faster inference at <1 pt accuracy loss
Having established that intermediate pre-training works, the next bottleneck is efficiency. Standard Transformer attention is quadratic in sequence length, which is problematic for large tables. Our idea with MATE: restrict attention to structural views — each token attends only to tokens in the same row OR same column, alternating across layers. This is an instance of axial attention, which has since become widely adopted in vision models like ViT and image generation architectures. [>>>] This reduces complexity from quadratic to linear while preserving the model's expressive power — we proved universal approximation. [>>>] [>>>] Practically, it doubles inference speed with less than 1 point accuracy loss, and it's a drop-in replacement for standard BERT attention.

MATE: Efficiency Gains

FLOPs comparison vs. sequence length

Peak memory usage

These plots confirm the theoretical gains. On the left: FLOPs grow linearly with MATE versus quadratically with full attention. The gap widens significantly for longer sequences. On the right: memory usage follows the same trend. This makes MATE practical for processing large tables that would otherwise exceed memory limits.

TabT5: From Understanding to Generation

Encoder-decoder architecture with structural embeddings for table-to-text generation

TabT5 shifts from understanding to generation. We extend the T5 encoder-decoder model with the same structural embeddings as TAPAS. The key innovation is the pre-training: de-noising corrupted tables AND "ToTTification" — learning to generate natural text descriptions from web tables. This again follows our "generation for understanding" recipe: learning to describe tables makes the model better at understanding them.

TabT5 Pre-training & Results

Pre-training Strategies

  • De-noising: reconstruct corrupted tables
  • ToTTification: generate related text from web tables

Results

  • Consistent gains on 4 benchmarks
  • Improved ToTTo, SQA, TabFact, FeTaQA
Chapter Takeaway: Structural embeddings + intermediate pre-training + encoder-decoder generation = comprehensive table understanding.
To summarize the tables chapter: we showed three complementary contributions. First, intermediate pre-training with synthetic data dramatically improves table fact verification. Second, MATE makes attention efficient for structured inputs with theoretical guarantees. Third, TabT5 demonstrates that generative pre-training on tables improves both generation and understanding tasks. [>>>] The code for all three is publicly available in the google-research/tapas repository. Now, what if the table isn't available as text at all — what if it's embedded in an image of a chart?

Incorporating Charts
into Models

Chapter 4

ACL 2023 (×2) · ACL 2024

Chapter 4 moves from structured text to truly visual inputs: charts and plots. Here we face an additional challenge — the data is embedded in pixels, not text tokens. We present two complementary approaches published at ACL 2023 and a follow-up at ACL 2024.

From Tables to Charts

Two complementary approaches

End-to-End

Image → Model → Answer

MatCha

Modular

Image → Table → LLM → Answer

DePlot

We explored two paradigms for chart understanding. MatCha is end-to-end: it processes chart images directly and produces answers. It's efficient and strong on extractive queries. DePlot is modular: it first converts the chart image into a structured data table, then hands it to any LLM for reasoning. This enables leveraging the LLM's reasoning capabilities — including few-shot and chain-of-thought. As we'll see, each excels in different scenarios, and they're complementary.

MatCha: Pre-training for Charts

Chart De-rendering

Image → underlying data table

Math Reasoning

MATH + DROP datasets for numerical computation

MatCha builds on the Pix2Struct architecture — an image-to-text model pre-trained by parsing web screenshots. We add two novel pre-training objectives. [>>>] Chart de-rendering: given a chart image, output the underlying data table. This teaches the model to "read" visual encodings — bar heights, line slopes, pie slices. Math reasoning: we take the MATH and DROP datasets and render the questions as images, so the model learns numerical computation in the visual domain. This is essential for answering quantitative questions about charts.

MatCha: Main Results

MatCha (300M params) outperforms PaLI-17B on chart tasks

MatCha, with only 300 million parameters, outperforms PaLI — a 17-billion parameter model — on chart-specific tasks. [>>>] This is a 56× size difference. It demonstrates that specialised pre-training with the right inductive biases can outperform brute-force scale. This validates our thesis: specialised, efficient models have enduring value.

MatCha: Ablation Study

Each pre-training component contributes; chart de-rendering has the largest impact

The ablation study shows that both pre-training components contribute, with chart de-rendering providing the largest gains. This makes sense: de-rendering forces the model to truly understand the visual encoding, acting as a strong self-supervised signal. Math reasoning adds complementary gains, especially on questions requiring computation. Again, generation (de-rendering) improving understanding — the recurring theme of this thesis.

MatCha: Fine-grained Analysis

MatCha excels at data extraction and math reasoning; visual attributes remain challenging

Breaking down by question category reveals an interesting pattern. MatCha excels on data extraction and math reasoning — exactly the capabilities targeted by our pre-training objectives. Plot attribute questions — such as "what color is the line?" or "how many legend entries?" — remain harder. These require low-level visual perception rather than data reasoning. This points to future work in richer visual encoding schemes.

DePlot: Modular Chart Reasoning

Translate chart → linearized table, then use any LLM for reasoning

DePlot takes a fundamentally different approach. Instead of answering directly, it translates the chart image into a linearized data table — essentially doing "chart de-rendering" as the primary task. Then any LLM can reason over the table. This is elegant because it decouples visual perception from reasoning, and allows leveraging the latest LLMs without retraining. Crucially, this enables one-shot and few-shot capabilities that end-to-end models can't easily achieve.

DePlot: Results

DePlot + LLM achieves 67.6% on ChartQA-Human (vs. 38.2% MatCha) with just one example

The results highlight the power of modularity. On human-authored questions — which require complex, multi-step reasoning — DePlot plus an LLM achieves 67.6%, nearly doubling MatCha's score. [>>>] The key is that LLMs excel at compositional reasoning once they have structured data to work with. On simpler extractive questions, MatCha is more competitive. The two approaches are truly complementary.

ChaTS-Pi: Faithful Chart Summarization

Extract data via DePlot, then verify entailment between summary and underlying table

ChaTS-Pi addresses a downstream application: chart summarization. The problem is that LLM-generated summaries of charts can contain hallucinated or unfaithful claims. Our solution uses DePlot to extract the data table, then checks whether each claim in the summary is entailed by the extracted data. This gives a faithfulness score — a measure of how trustworthy the summary is. This connects to the next chapter on uncertainty: knowing when to trust model outputs.

Charts Chapter Summary

  • MatCha: End-to-end → strong on extractive & synthetic queries
  • DePlot: Modular → excels on complex human queries with LLM reasoning
  • ChaTS-Pi: Faithfulness scoring → reliable chart summaries
"What I cannot create, I do not understand" — R. Feynman
To summarize: MatCha and DePlot are complementary — one is efficient and end-to-end, the other is modular and leverages LLM reasoning. ChaTS-Pi shows a practical application combining both ideas. [>>>] The Feynman quote captures the essence: by learning to de-render — to "create" the data from pixels — the model demonstrates genuine understanding. Chapter 5

EMNLP 2023 · ACL 2024

Chapter 5 asks a different question: even when models are accurate, can we trust their answers? High accuracy on benchmarks doesn't mean the model knows when it's wrong. This is critical for real-world deployment, especially for assistive technology serving visually impaired users.

When Models Should Say "I Don't Know"

Sampled outputs from an LMM on a VizWiz-VQA example used to measure calibration

This figure illustrates the core idea. Given an ambiguous image and question, we sample multiple outputs from the model. If the samples are consistent — the model is confident. If they diverge — the model is uncertain and should abstain. The VizWiz-VQA dataset is particularly relevant here: it was created by visually impaired users taking photos with their phones. The images are often blurry or poorly framed, making many questions genuinely unanswerable.

Scoring Methods

Existing Methods

  • Likelihood: \(P(y|x)\) from the model
  • Sampling Repetition: most frequent answer ratio
  • Sampling Diversity: proportion of distinct answers

Our Proposal

Avg BLEU

Average pairwise semantic similarity among sampled outputs

\(\text{Score} = \frac{1}{\binom{n}{2}} \sum_{i < j} \text{BLEU}(s_i, s_j)\)

We compared several confidence scoring methods. Model likelihood seems natural but is poorly calibrated in practice — models are often overconfident. Sampling repetition and diversity are better but brittle to surface-level variation. Our proposal, Avg BLEU, computes the average pairwise BLEU score among sampled outputs. It captures semantic agreement rather than exact string matching. The intuition: if all samples say similar things in different words, the model is confident. If they say completely different things, it's uncertain.

Calibration Results

Avg BLEU consistently outperforms alternatives across ECE, ROC-AUC, and Coverage@Acc

Looking at the chart, we can now compare methods side by side on each metric. [>>>] Avg BLEU consistently outperforms all alternatives on both expected calibration error and ROC-AUC. Importantly, it works across different model types and scales, and it requires no access to model internals, making it applicable even to black-box APIs.

Calibration: The Ideal

A well-calibrated model's confidence should match its accuracy — the ideal is the diagonal

What does good calibration look like? Ideally, when we plot a model's confidence score against its actual accuracy, the curve should follow the diagonal line. A point on the diagonal means: when the model says it's 80% sure, it's right 80% of the time. Deviations above the diagonal mean the model is under-confident; below means over-confident. Most current models fall well below the diagonal — they are systematically over-confident.

LMMs vs. LLMs: Calibration Gap

Text-only LLMs

  • Reasonably calibrated on factual tasks
  • Confidence tracks difficulty
  • Well-studied mitigation strategies

Large Multimodal Models

  • Adding vision introduces new sources of uncertainty
  • Image quality, visual ambiguity, layout complexity
  • Generally less calibrated than text-only counterparts

Visual modalities make calibration harder — which makes uncertainty quantification even more important

A key finding: adding the visual modality introduces new sources of uncertainty that text-only models don't face. Image quality varies — think of the blurry photos in VizWiz taken by visually impaired users. Layout complexity adds ambiguity. Visual attributes can be subtle. [>>>] LMMs are generally less well-calibrated than LLMs on equivalent tasks, which makes our uncertainty work even more important for multimodal systems. This has direct implications for deploying these models in assistive technology.

Uncertainty Chapter Summary

  • High accuracy ≠ reliable — calibration matters for real users
  • Avg BLEU: simple, effective, sampling-based uncertainty metric
  • Critical for assistive technology (visually impaired users)

Key Insight: Knowing what you don't know is as important as knowing.

The takeaway: building models that can say "I don't know" is just as important as building accurate models. Avg BLEU provides a practical, easy-to-implement solution. [>>>] One important caveat: it's hard to compare calibration scores across models with different underlying accuracy. Taken to the extreme, a model that is always wrong but always knows it's wrong would appear perfectly "calibrated" — but it's not a useful model. Calibration only matters when paired with reasonable accuracy. This work was partly motivated by real users — VizWiz is created by visually impaired people who rely on these models daily. Getting a wrong answer confidently is worse than getting no answer at all.

The final two chapters address temporal aspects of language. Chapter 6 asks: can language models learn new words? And if so, what is the best way to teach them — through examples in context, or through dictionary definitions? This paper received the Outstanding Paper Award at EACL 2023.

WinoDict: Can Models Learn New Words?

What is a Winograd schema?

A sentence pair where changing one word flips the coreference resolution of a pronoun. Correctly resolving "it" requires understanding word meanings:

"The trophy doesn't fit in the suitcase because it is too large." → it = trophy
"The trophy doesn't fit in the suitcase because it is too small." → it = suitcase

The WinoDict twist

Replace "trophy" with a novel word:

"The glorp doesn't fit in the suitcase because it is too large."

glorp (n): a shiny metal award given as a prize

Can the model use the definition to resolve "it"?

We test: definitions, in-context examples, and combinations

Winograd schemas are a classic AI test — they're a great benchmark because they require genuine language understanding, not just pattern matching. [>>>] Here's how they work: two sentences differ by a single word — "large" vs "small" — and that swap changes which noun the pronoun "it" refers to. You need to understand the meaning of the key noun to get this right. [>>>] WinoDict takes this a step further: we replace the key noun — "trophy" — with a made-up word like "glorp" and provide only a dictionary definition. The question is not just whether models CAN learn new words in context, but what is the best way: definitions, usage examples, or both? This is in-context word acquisition — something humans do effortlessly but models find surprisingly hard.

WinoDict: Key Results

Main Findings

  • All models show significant accuracy drops with novel words, even with definitions
  • Human performance remains stable
  • Definitions help, but less than expected
  • Larger models do better, but a substantial gap with humans remains

Teaching Methods Compared

  • Definition only: modest improvement
  • Examples only: comparable to definitions
  • Both combined: best results, but still far from human
All models tested — from GPT-3 to PaLM — show significant accuracy drops when key words are replaced with novel ones, even with correct definitions provided. This demonstrates that LLMs rely heavily on lexical associations learned during training rather than genuinely reasoning from definitions. Human performance remains stable, confirming that the task is solvable with the provided information. Interestingly, combining definitions with usage examples works best, but even then there's a substantial gap with human performance.

What Makes a Word Hard to Learn?

Accuracy breakdown by word properties: concreteness, frequency, and number of senses affect learnability

This breakdown reveals what makes some words harder to learn than others. Concrete words — words referring to physical objects — are easier than abstract ones. Words with fewer senses are easier: polysemy creates ambiguity that definitions struggle to resolve. Interestingly, word frequency in the training data matters less than concreteness, suggesting the challenge is fundamentally about grounding meaning, not just exposure.

Vocabulary Chapter Summary

  • LLMs struggle with in-context word acquisition
  • WinoDict provides a controlled benchmark for measuring this limitation
  • Human evaluation confirms the gap between human and model performance

This limitation motivates the next chapter: not just words, but facts evolve over time.

WinoDict reveals that models have brittle lexical representations. [>>>] This connects to a broader theme: language and knowledge are not static. If models can't handle new words, can they handle changing facts? That's what we explore next.

Chapter 7 addresses temporal knowledge. Language models are trained on data from a specific time period, but the world changes. What happens when facts expire?

TempLAMA: Facts Change Over Time

The Problem

"Who is the president of [country]?" — the answer changes over time

LMs trained on static snapshots → stale knowledge

TempLAMA Examples

"___ is the head coach of Real Madrid CF."
2015: Ancelotti · 2018: Zidane
"Cristiano Ronaldo plays for ___."
2012: Real Madrid · 2019: Juventus
"___ is head of gov. of the UK."

Many factual assertions have temporal scope: political leaders change, sports records get broken, team rosters shuffle. Models trained on a 2020 snapshot might say "Donald Trump is the president" regardless of when they're asked. TempLAMA is our benchmark: over 50,000 cloze-style queries derived from Wikidata, where the correct answer changes depending on the year. Here are some examples — you can see that the same query has completely different answers just a few years apart.

Jointly Modeling Text and Time

Different training strategies for temporal data

Uniform

Single model trained on all data — ignores time

Cheap but conflates time periods

Yearly

Train separate model per time period

More expensive, better at memorization

Temporal

Single model with time metadata in input

Efficient, better calibration for future

We compared three approaches for incorporating time. The diagram on the left shows the key difference: the Uniform model sees all data without timestamps; the Yearly approach trains separate models; and our Temporal approach conditions a single model on a date prefix. The Temporal model is essentially next-token prediction conditioned on a date — a simple but powerful idea. It generalises better to unseen future time periods and naturally becomes less confident about facts far from its training period.

Memorizing Facts Across Time

Temporal models improve memorization of seen facts and scale better to new time periods

This chart shows fact recall accuracy across time periods. Crucially, each model is trained with a temporal cutoff — it only sees data from before a certain date. We then test how well it recalls facts from both seen and unseen periods. The temporal model consistently outperforms the baseline and shows smoother degradation for future periods it hasn't been trained on. This idea of training with a strict temporal cutoff has recently been explored at larger scale — for example, Talkie is a 1.3B-parameter LLM trained exclusively on pre-1931 text, showing how temporal conditioning shapes what a model can and cannot know.

Better Calibration & Cheaper Adaptation

Graceful degradation on unseen future facts

Efficient adaptation with new data (α = mixing ratio)

Two additional benefits emerge. Left: the temporal model naturally becomes less confident about facts from distant time periods — graceful degradation rather than confident hallucination. This connects to Chapter 5 on uncertainty. Right: the adaptation experiment. We have a model trained on 2010–2018 data and want to update it with new 2019 data. The parameter alpha controls the mixing ratio — alpha is the fraction of training examples drawn from the new 2019 segment, with the rest coming from old segments. At alpha=0.5, just 10K additional training steps match the performance of a model retrained from scratch for 300K steps. The temporal model is much more robust to this adaptation — it maintains performance on old facts while learning new ones, whereas the uniform model degrades rapidly on past facts.

Time Chapter Summary

  • Adding temporal metadata is simple but powerful
  • Improves memorization, calibration, and efficient adaptation
  • Together with WinoDict: both words and facts evolve — static models are incomplete
Chapters 6 and 7 together make the case that language models need to be dynamic. Words evolve (WinoDict) and facts evolve (TimeLM). Static training on a single snapshot is fundamentally insufficient for reliable systems. This completes the technical contributions. Limitations & Ethics

Limitations

  • English-centric datasets
  • Some single-run results
  • Prompt sensitivity in LLM experiments
  • Synthetic benchmarks vs. real-world complexity

Ethical Considerations

  • Bias from web-crawled pre-training data
  • Risk to visually impaired users from confident errors
  • Environmental impact of large-scale training

I want to be transparent about limitations. Most of our datasets are English-only — multilingual visual language understanding remains largely unexplored. Some results are based on single runs due to computational constraints. On the ethical side, the most pressing concern is deploying these models for assistive technology: a confident wrong answer to a visually impaired user can have real consequences. This directly motivated our uncertainty work. We've tried to mitigate environmental impact by focusing on efficient models and releasing everything publicly to avoid redundant retraining.

This is especially urgent now that LLMs are being incorporated into data science workflows — bad, misleading, or color-blind unfriendly data visuals are already prevalent, and we need to make sure our models avoid producing them.

Four cross-cutting learnings that emerge from the thesis. [>>>] First, the symbiosis of understanding and generation: in every chapter, generative objectives improved understanding tasks. This is the "modern recipe" validated empirically. [>>>] Second, the web is full of structured visual language that provides free self-supervised training signal. [>>>] Third, specialised models matter. MatCha at 300M parameters beats PaLI at 17B. And this principle extends to current practice: even today's largest SOTA models with hundreds of billions of parameters rely on annotations and feedback generated by smaller, specialised expert models. [>>>] Fourth, we need to look beyond accuracy: calibration, faithfulness, and temporal validity are what actually matter for users. [>>>] Now, with massive LLMs seemingly solving everything, one might ask: was this specialised work for nothing? Not at all. Once you look under the hood of large multimodal models, you find the same techniques we developed: chart de-rendering is now a standard pre-training task, table structure encoding is baked into modern architectures, and axial attention patterns are everywhere in vision transformers. The contributions aren't superseded by scale — they're absorbed into it. And critically, the hardest problems we tackled — continual learning, hallucination, and calibration — remain among the biggest open problems in the field. These aren't solved by making models bigger.
